Prompt: Modify blog post structure for short, visually appealing posts

Purpose
Make a Markdown blog post short, concise, and visually appealing while preserving Jekyll front matter and adding an appropriate References section.

Expected inputs
- `content` (required): Full post Markdown including Jekyll front matter if present.
- `tone` (optional): one of `neutral` (default), `casual`, `academic`, `technical`.
- `max_words` (optional): integer. Target maximum word count for the body (default 200).
- `citation_style` (optional): one of `numeric` (default), `APA`, `IEEE`, `MLA`.
- `include_featured_image` (optional): boolean. If true, suggest a featured image and alt text.
- `preserve_front_matter` (optional): boolean. If true (default), keep original front matter and only update `excerpt` and `image` keys.

Instructions for the assistant
1. Parse the input Markdown. If front matter (--- delimited) exists, preserve it exactly except update or add `excerpt` and `image` keys when applicable.
2. Produce an output Markdown that:
  - Keeps or restores original front matter at top.
  - Starts with a one-line title (use existing title from front matter if present).
  - Provides a single-sentence lead (intro) of 10–20 words.
  - Presents 2–4 very short paragraphs (20–60 words each) explaining the idea — keep language simple and concise.
  - Use at most one 3–5 item bullet list for key takeaways or steps.
  - Add a highlighted one-line takeaway as a blockquote or callout.
  - If `include_featured_image` is true or if the post lacks an image, suggest a `featured_image` filename and an `alt` description, and add or update the `image:` key in front matter.
  - Add an `excerpt:` field to front matter with a 20–30 word summary.
3. References and citations
  - Extract any inline URLs or bibliography items from the original content when present.
  - Create a `References` section at the end with numbered entries. Use numeric markers like [1], [2] in-text.
  - Format numbered references as Markdown links. If `citation_style` is `APA` or `IEEE` or `MLA`, follow that style for the reference text while still leaving a clickable URL.
4. Length and tone constraints
  - Ensure the main body (excluding front matter and References) does not exceed `max_words` words. When needed, shorten sentences, prioritize key points, and remove examples or long digressions.
  - Follow `tone` for wording and register.
5. Accessibility and visual cues
  - Recommend an image with a short `alt` description when applicable.
  - Use headings (`##`) sparingly: one `## References` at the end is required; otherwise prefer bold or small headings for sections.
6. Output format
  - Return a single Markdown string ready to replace the post file. Keep front matter at top.
  - After the Markdown, provide a 2-line summary explaining what changed (excerpt added, image suggested, references normalized) and list any ambiguous items that need user input.

Example invocation
{
  "content": "---\ntitle: My Topic\n---\nLong original post content...",
  "tone": "neutral",
  "max_words": 180,
  "citation_style": "numeric",
  "include_featured_image": true
}

Example output snippet
---
title: My Topic
excerpt: A concise 25-word summary of the post.
image: assets/images/my-topic-feature.jpg
---

My Topic

Lead sentence in one line.

Short paragraph 1.

Short paragraph 2.

**Key takeaways**
- Item 1
- Item 2

> Takeaway: One-line conclusion.

## References
[1] Author, Title, Year. https://doi.org/...

Summary of changes: excerpt added; suggested featured image; references normalized.

Clarifying questions (ask user when ambiguous)
- Preferred citation style: `numeric` / `APA` / `IEEE` / `MLA`?
- Maximum target word count (default 200)?
- Do you want the assistant to automatically overwrite existing posts or only produce drafts for review?
